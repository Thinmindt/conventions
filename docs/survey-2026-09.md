# How this plugin compares with published agentic-engineering practice (2026-09-27)

A snapshot, not a plan: what companies running "software factories" and practitioners known for
using coding agents well have published, set against this plugin as of version 1.1.0. The plan
that follows from it is [ROADMAP.md](ROADMAP.md); section numbers there are cited below as §n.

**How the sources were read.** Anthropic's engineering posts and docs, HumanLayer's ace-fca.md,
and the public repositories named below (ghuntley/how-to-ralph-wiggum, obra/superpowers,
EveryInc/compound-engineering-plugin, steipete/agent-scripts) were read in full. Most personal
blogs and company posts (warp.dev, openai.com, stripe.dev, simonwillison.net and others) could
not be fetched from the survey's sandbox; for those, the summary rests on search-engine extracts
of the page at the URL given. Treat quoted phrases from them as close paraphrase and re-read the
source before citing it.

---

## 1. Where this plugin already agrees

| This plugin | Who does the same |
|---|---|
| One gate script, run identically locally and in CI | Stripe Minions ("shift feedback left", lint in seconds on every push); OpenAI harness engineering (mechanical enforcement); Anthropic best practices ("give Claude a way to verify its work") |
| python-traps: each rule names the failure it prevents, "paid for once" | Mitchell Hashimoto ("engineer the harness": every agent mistake becomes an AGENTS.md line or a tool); Geoffrey Huntley ("stdlib" of rules from what went wrong); Boris Cherny (every mistake goes into CLAUDE.md); Every's compound step |
| Design documents with what, why and when; roadmap as the plan as it stands, with an archive | OpenAI (`docs/` as system of record: design-docs, exec-plans active and completed, tech-debt tracker); Huntley (`specs/` plus `IMPLEMENTATION_PLAN.md`); Anthropic long-running harness (progress file); Warp (`specs/` holding product and tech spec before code) |
| Roadmap entries say what "done" means | Warp (`ready-to-spec` then `ready-to-implement`); Harper Reed and Addy Osmani (spec, then plan, then execute); Eugene Yan (success criteria beat implementation-level plans) |
| doc-audit: a periodic hard look at every document | OpenAI's recurring doc-gardening agent; Steve Yegge's daily `bd doctor`; Huntley's plan cleanup |
| Rules delivered as skills that load when the work calls for them | Anthropic context-engineering guidance (smallest set of high-signal tokens, just in time); HumanLayer (progressive disclosure); Every and steipete (conventions shipped as a shared, versioned package) |
| Hardware behind a boundary, enforced by a banned-import lint | OpenAI's layered architecture enforced by custom lints and structural tests |
| check_private.sh on every public project | GitHub's secret scanning on agent-written code. No practitioner surveyed publishes a check for personal terms (names, hosts, addresses); this one goes further than the others |

The strongest match is OpenAI's harness-engineering setup: a short table of contents over a
`docs/` directory that is the system of record, kept true by a recurring agent. This plugin has
the documentation discipline; it lacks the table of contents and the recurrence (§2, §8, §11).

## 2. Where this plugin differs

These are differences of approach, and several are defensible as they stand.

- **Conventions are written by hand, not learned.** Warp Factories run an outer "self-improvement"
  agent that watches maintainers correct the inner agents and opens PRs editing the skill files.
  Every's compound step and Cherny's `@claude` on PRs write lessons back as part of each change.
  Here a lesson becomes a rule only when someone remembers to write it (§6).
- **Enforcement is mostly advisory.** Anthropic's guidance is that what must happen every time
  belongs in a hook, because CLAUDE.md and skills are advisory; HumanLayer puts it as "Claude is
  not a linter". Martin Fowler's site (Birgitta Böckeler, "Harness engineering") splits the
  harness into guides, which steer before the agent acts, and sensors, which check after. This
  plugin is nearly all guides. Its only sensor is the gate, which runs when someone runs it (§4,
  §12).
- **Humans review everything.** StrongDM's factory forbids human-written and human-reviewed code
  and grades against hidden end-to-end scenarios instead. OpenAI makes human review optional.
  Stripe, Copilot's coding agent, Simon Willison, Karpathy and Hashimoto keep a human accountable.
  This plugin's model (branch, review, never push as part of an audit) sits with the second group.
  That fits one owner with unattended services, where a quiet failure is expensive.
- **Scope is how code is written, not how a change is carried out.** Every surveyed workflow
  (Anthropic's explore → plan → code → commit, HumanLayer's research → plan → implement,
  Superpowers' brainstorm → plan → TDD → review, Every's plan → work → review → compound) covers
  the loop itself. This plugin covers style, traps and documents, and leaves the loop to the
  agent (§9, §10).
- **Rules are global, not scoped by directory.** Stripe, Amp, Copilot and the AGENTS.md standard
  scope rules to subdirectories. For a single-language personal toolkit, global rules plus skill
  triggering are a reasonable substitute. A `paths:` scope on python-style is the cheap step
  toward the same effect (§5).
- **Packaging is Claude-only.** Warp, Codex, Copilot, Amp, Cursor and Factory read AGENTS.md, now
  a Linux Foundation standard. The rules in this plugin are tool-neutral prose, but only Claude
  Code loads them. steipete/agent-scripts, the closest published analogue to this repository,
  keeps one AGENTS.md and links it into every agent's config (§8).

## 3. What this plugin overlooks

Most cited first:

1. **No evaluation of the skills themselves.** Nothing shows that python-traps loads when a
   threaded consumer is written, that python-style stays out of a JavaScript session, or that
   either changes the result. Hamel Husain, Anthropic's tools and evals posts, and Jesse Vincent
   (pressure-testing Superpowers skills with subagents) treat this as the core practice.
   `claude plugin eval` now exists for this, with a with/without ablation (§5).
2. **No deterministic enforcement at the moment of change.** There is no PreToolUse, PostToolUse
   or Stop hook, and no git hook. The privacy rule, whose failure is the costliest to undo (pushed
   history), is enforced only if the gate is run before the push (§4).
3. **No loop from mistake to rule** (§6), covered in §2.
4. **The documentation rules are hidden inside python-style.** Design documents, plans and the
   roadmap rule apply to every project. A project with no Python has no reason to load a skill
   named python-style (§3).
5. **This repository has no agent guide of its own.** It has no CLAUDE.md or AGENTS.md, though
   its own doc-audit table gives the agent guide a role. The rules a contributor or an agent must
   know are in the README or nowhere: bump the version, keep STYLE.md in sync, run the gate (§8).
6. **Setting up a project and checking for drift are manual.** STYLE.md and check_private.sh are
   copied by hand, and drift is found with a `diff` someone has to remember (§7).
7. **The doc-audit reminder assumes a persistent home directory.** The last-audit stamp lives
   under `~/.local/state`. On an ephemeral machine, such as a cloud session container, every
   session reports that no audit is recorded. On a second workstation the audit is repeated (§2).
8. **No fresh-context reviewer.** Anthropic, Every and Superpowers review in a separate context
   (a subagent or second session) because the writer's context is biased toward its own
   choices (§10).
9. **Few rules are mechanised.** OpenAI turns "golden principles" into custom lints whose messages
   say how to fix the problem. Amp runs one agent per check file. Several python-style and
   python-traps rules map directly onto existing ruff rules, and the guide does not name them (§12).
10. **No guidance for running agents unattended.** Willison's "lethal trifecta" (private data,
    untrusted content, a way out), permission allowlists over skipping permissions (Cherny),
    containers (Willison, Carlini). python-traps covers unattended Python services, but not
    unattended agents (§14).
11. **Plugin hygiene is manual.** `claude plugin validate --strict` passes today, but the gate does
    not run it. Versions are bumped by hand with no check. CI actions are pinned by tag, not
    commit, and the workflow does not restrict its token's permissions (§1, §13).

## 4. Where the voices disagree

Not everything above is consensus. Before adopting a practice, weigh it against these:

- **Specs and subagents.** Peter Steinberger rejects spec-driven setups, subagents and elaborate
  tooling ("just talk to it"), and ships code he has not read. Böckeler found heavyweight
  spec-driven tools turn a small bug into a dozen acceptance criteria. Anthropic's own guidance:
  skip the plan when the diff fits in one sentence.
- **Hooks.** Armin Ronacher tried hard to make hooks pay off and saw no gain, partly because he
  runs without permission prompts. Most others (Anthropic, HumanLayer, Harper Reed's pre-commit
  hook) favour deterministic enforcement.
- **Compaction.** Amp replaced compaction with handoff in 2025 and brought it back in 2026 as
  models improved. Context advice changes quickly; date it.
- **Review.** StrongDM and OpenAI move review to agents and hidden scenarios. Willison, Ronacher
  ("agent psychosis") and Osmani ("comprehension debt") warn that unreviewed agent output is
  a cost pushed onto someone else.
- **Reviewers find what they are asked to find.** Anthropic warns that a reviewer asked for gaps
  always reports some, and chasing all of them over-engineers. A reviewer agent should look for
  rule violations and bugs, not "improvements".
